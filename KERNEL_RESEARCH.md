# Linux kernel capability research

Keep FLOWCORE in userspace. The stock kernel can classify traffic with administrator-controlled policies, pace supported sends, attach metadata to a socket and expose the queue state needed by the tested control loop. The study also reproduced a limit of ordered TCP delivery and an ancillary-data asymmetry between TCP and UDP. Neither supplies a kernel mechanism with a demonstrated application benefit. [Experiments](KERNEL_EXPERIMENT_RESULTS.md) · [API decision](KERNEL_API_PROPOSAL.md)

The motivating observations are in the earlier matched-allocation study. Hybrid and static started with identical class allocations. Hybrid made zero policy changes and the comparison did not establish a lower P99. We investigated whether the controller lacked a kernel operation, sampled the wrong timescale, or was asking a transport to provide different delivery semantics. [FLOWCORE benchmark report](BENCHMARK_REPORT.md#separately-preregistered-same-allocation-check)

## Upstream capability review

We inspected Linus's tree at [d48723711bae9b8cdc56719c448ba42fef28cbee](https://github.com/torvalds/linux/commit/d48723711bae9b8cdc56719c448ba42fef28cbee) and ran probes on the installed Fedora ARM64 kernel. The source revision and the distribution build are separate evidence.

FQ schedules flows and departure times. fq_codel combines per-flow scheduling with queue-delay control. CAKE offers a shaped scheduler with flow isolation. | A socket label takes effect only through configured policy. Class guarantees apply at the local bottleneck. ## Candidate gaps

| Required behavior and affected applications | Demonstration and current limit | Benefit and compatibility trade-off | Decision |
|---|---|---|---|
| Associate a durable, trusted policy hint with each owned TCP or UDP socket for SDK clients and service meshes. | FLOWCORE can attest an FD with `SCM_RIGHTS` and correlate its cookie. The stock socket-storage probe distinguishes two sockets, shares metadata through duplicated FDs and rejects inheritance by numeric FD reuse. Marks and priorities provide selectors with narrower semantics. | Socket storage avoids a PID or FD-number table in the kernel. An authorized map writer still needs quotas and explicit handling of socket, map and lease lifetime. Existing cookie-based reporting remains usable where BPF is unavailable. | Existing mechanisms cover the demonstrated requirement. |
| Send a time-sensitive UDP message before queued bulk datagrams in a cooperative media, control or QUIC sender. | Per-message priority and transmit-time cmsgs worked in stock UDP. ETF reported expiry through the error queue. FQ held a monotonic UDP send until close to the requested time. | Use application-selected datagram scheduling, bounded queue resources and separate policy for congestion. Older kernels and nonparticipating schedulers require feature detection. A QUIC datagram can contain frames associated with multiple streams. | Existing datagram interfaces cover the demonstrated requirement. |
| Deliver a later urgent record before an earlier delayed record on one TCP connection for mixed RPC and bulk workloads. | In all 12 shared-stream trials the urgent segment reached the receiver first. The application still received the prefix before the urgent bytes. The dedicated connection met the 100 ms fixture budget. The TCP cmsg probes also observed different behavior from UDP. | Giving a later skb an earlier dequeue opportunity cannot remove the ordered receive dependency. Before committing bytes to TCP, the application can choose a send order. Independent connections or a suitable multiplexed transport can give requests separate delivery domains. Additional connections cost state and can distort per-flow fairness, so an operator needs aggregate limits. | The observed limit follows from the transport contract. The TCP cmsg asymmetry is a separate API behavior with no measured need for a new TCP option. [TCP specification](https://www.rfc-editor.org/rfc/rfc9293.html) · [QUIC streams and packet format](https://www.rfc-editor.org/rfc/rfc9000.html) |
| Detect short local class pressure with bounded overhead for adaptive QoS controllers. | Two samples about a second apart missed an isolated queue pulse. Faster `RTM_GETQDISC` queries saw it. Native class reads matched `tc` and reduced quiet-read cost. Sampling still misses events that occur between polls. | Direct reads can reduce subprocess cost and offer a higher useful cadence. Faster dumps still consume kernel and userspace CPU, and a stable scheduler-independent event feed would have ABI and backpressure costs. Existing tracepoints and scheduler instrumentation are additional candidates. | Validate native polling under load before pursuing an event ABI. |
| Report request success, cancellation and deadline misses cheaply from an application runtime. | FLOWCORE already has a bounded application event protocol and shared-session batching. Neither kernel TCP counters nor packet classifiers can reconstruct application outcomes. Prior SDK tests found delivery loss under contention. | A bounded, loss-accounted userspace path can preserve request semantics and avoid per-request kernel state. A privileged report path would expose new denial-of-service and authorization surfaces. | Treat delivery reliability and batching as userspace work. [Intent protocol](INTENT_API.md) |

## Upstream route if the evidence changes

Start with the smallest affected subsystem. Socket and TCP behavior belong with the networking socket and TCP maintainers. Traffic scheduler and rtnetlink changes belong in the networking traffic-control path. BPF map, helper or TCX changes also involve BPF maintainers. MPTCP changes have a separate maintainership entry and list. Use `scripts/get_maintainer.pl` on an actual diff and check both lore and netdev/BPF Patchwork for related work. The reviewed tree already contains a per-message priority selftest and qdisc BPF code. [Maintainers](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/MAINTAINERS) · [Priority selftest](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/tools/testing/selftests/net/cmsg_so_priority.sh) · [Netdev guidance](https://docs.kernel.org/process/maintainer-netdev.html)

An eventual feature RFC needs a user-visible reproducer, an existing-API baseline, reviewable changes with a userspace example, and focused kselftests in the same series. Check the target tree and subject prefix, explain compatibility and benchmark cost, and use `checkpatch.pl`. A human contributor reviews the submission and certifies their DCO. The source review here supports keeping kernel work at the investigation stage. [Submitting patches](https://docs.kernel.org/process/submitting-patches.html) · [Kselftest](https://docs.kernel.org/dev-tools/kselftest.html) · [AI tool guidance](https://docs.kernel.org/process/coding-assistants.html)
