# Kernel API proposal decision

Retain FLOWCORE's versioned userspace intent protocol and use Linux's existing socket and TC interfaces for enforcement. The evidence supports a cheaper queue read path and separate delivery domains for urgent traffic. It leaves the case for a new kernel ABI open only if a workload remains blocked after those mechanisms are evaluated. [Capability review](KERNEL_RESEARCH.md) · [Experiments](KERNEL_EXPERIMENT_RESULTS.md)

## Interface and data model

| Boundary | Interface and state | Lifetime, ownership and failure behavior |
|---|---|---|
| Application to FLOWCORE | Existing V2 registration, request events and optional socket-FD attestation. Userspace holds service policy, request ID, monotonic budget, outcome and association. | The service lease and authenticated process own the report and association. Preserve expiration and caps on inflight requests and cookies. A missing or dropped report is unknown coverage. Preserve an application's own deadline even when reporting is unavailable. [Intent API](INTENT_API.md) |
| Socket to authorized classifier | Existing `sk_priority` and `sk_mark` with explicit policy. Where useful, an operator can populate `BPF_MAP_TYPE_SK_STORAGE` by a verified socket FD. Its optional opaque value is private to the policy map. | The kernel associates storage with a socket object. Duplicated FDs share it. A new socket with the same numeric FD has distinct storage. The map and socket lifecycle bound reclamation. FLOWCORE would have to enforce quota and lease expiry separately and remove metadata on revocation. [Socket storage](https://docs.kernel.org/bpf/map_sk_storage.html) |
| Packet to scheduler | Configured TC classes provide local bandwidth policy. Cooperative UDP sends may supply priority and a transmit timestamp on supported paths. FQ and ETF consume their respective timing and pacing state. | Priority and mark are inputs to an administrator's classification. Keep an ordinary class for missing or unauthorized metadata. Unsupported options return an error or have a protocol-specific effect, so confirm behavior before advertising the capability. Handle ETF rejection as a send outcome. The application owns retry and cancellation. [Socket source](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/net/core/sock.c) · [ETF source](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/net/sched/sch_etf.c) |
| Kernel to FLOWCORE | Existing rtnetlink class and qdisc dumps provide counters. Reuse the bounded netlink reader and probe support per target namespace and interface. | Bind reads to an admitted namespace and validate ifindex and object generation. Treat truncation, interrupted dumps, counter resets and unsupported attributes as stale observations. Preserve a verified policy on observation failure. Never substitute zero pressure for a failed read. [TC family](https://docs.kernel.org/next/networking/netlink_spec/tc.html) |

The research readers only compare statistics. Production adoption would need the full readback used in admission and actuation, including class rates, ceilings, priorities, hierarchy, ownership and generation. A production reader should keep a bounded queue of outstanding requests, validate sender and sequence, and resynchronize after link or object churn. Measure the trade-off between sample cadence and RTNL contention at representative class counts before switching the controller to it.

## Privilege and compatibility

The SDK should remain unprivileged. On the tested kernel, a zero-capability process set priority 6 and enabled monotonic `SO_TXTIME`. Priority 7, a nonzero mark and TAI `SO_TXTIME` were denied. The reviewed source accepts `CAP_NET_ADMIN` or `CAP_NET_RAW` for elevated priority and marking and checks `CAP_NET_ADMIN` for non-monotonic transmit clocks. TC changes and privileged BPF operations belong to the operator in an admitted namespace. Keep the map FD and policy-writing capability out of untrusted clients. [Socket capability checks](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/net/core/sock.c#L461) · [Experiment permissions](KERNEL_EXPERIMENT_RESULTS.md#privilege-and-lifetime)

An integer priority, DSCP value or mark asserted by an application cannot attest tenant identity. Resolve authorized policy from the lease and verified transport association. Recheck socket and namespace identity, cap the number of admitted sockets and separate policy map ownership from read access. A classifier must tolerate absent socket context and stale generations. If a map or hook fails, use the configured default class. Limit instrumentation to owned interfaces, bound event buffers and count losses. The prototype storage probe is evidence for identity semantics only. It does not establish BPF attach policy, resource consumption at scale or cross-namespace isolation for a production feature.

TCP applications can select a dedicated connection before bytes enter the stream or schedule requests in their own protocol. Preserve class-level fairness across the additional flows. On an established TCP stream, appending a later request preserves the stream's byte order. A cooperative QUIC stack can choose the streams to packetize before encryption, and socket hints remain at datagram or connection granularity. Policy versions and feature negotiation stay in the existing V2 interface. [TCP ordered delivery](https://www.rfc-editor.org/rfc/rfc9293.html) · [QUIC stream prioritization](https://www.rfc-editor.org/rfc/rfc9000.html#name-stream-prioritization)

## Evidence required to reopen kernel design

A possible research question is whether a controller can capture class backlog transitions within a fixed CPU and loss budget when normal dumps and available tracepoints are both insufficient. A second is whether a real, non-multiplexed TCP application benefits from a supported per-write hint without needing receive reordering. The current evidence establishes neither unmet requirement.

1. Name the concrete application, local policy, latency objective and required observation or actuation timescale. Build a reproducer that also measures losses, actual class occupancy, CPU and fairness.
2. Compare a persistent rtnetlink reader, adaptive sampling and bounded tracing for the observation case. For the send case, compare transport-aware userspace scheduling, flow separation and existing per-socket or per-datagram knobs. Test the current stock kernel and an independent target. Keep workload, initial rates, deadlines and failure accounting fixed.
3. If a failure persists, isolate a minimal missing operation with a measurable benefit. Prefer a scoped change to an existing interface when it preserves current semantics. A future observer could be read-only and opt-in with bounded state and explicit loss reporting. Define exact object identity, lifetime, namespace, authorization, event units and timestamp clock before proposing an ABI.
4. Prototype only in a disposable guest with a known-good boot image, snapshot recovery and a console. Boot stock and candidate kernels in the same fixture. Test option validation, FD/object reuse, concurrent updates, namespace teardown, bounded resources and rollback. Compare the exact same offered workload across the current FLOWCORE backend, the best stock API backend and the candidate.
5. Reopen upstream review only after the benefit survives held-out runs and fairness, CPU and compatibility limits. Keep any netdev/BPF RFC small and include the reproducer, ABI rationale and tests. [Netdev guidance](https://docs.kernel.org/process/maintainer-netdev.html) · [Kselftest](https://docs.kernel.org/dev-tools/kselftest.html)

The design decision introduces no kernel option number, structure layout or scheduler hook. The experiment program exercises the shipped kernel from userspace.
